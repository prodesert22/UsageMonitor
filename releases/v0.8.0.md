# v0.8.0

Brings theming to the KDE Plasma widget: five bundled themes, any KDE color
scheme already installed on the system, custom themes you name and edit
yourself, and a transparency slider that works in every mode. The CLI is
unchanged.

## Added

- **Theme settings page.** A fourth page in the plasmoid configuration window
  with four modes:
  - **Follow the current desktop theme** (default) — no colors of our own,
    every token falls back to `Kirigami.Theme`, so the widget looks exactly as
    it did before.
  - **Built-in theme** — macOS Dark, macOS Light, Nord, Dracula, Tokyo Night.
  - **Installed KDE theme / color scheme** — any `.colors` scheme or Plasma
    desktop theme found on the system, including third-party ones from the KDE
    Store (the macOS look-alikes land here).
  - **Custom** — your own named themes, with New/Delete, a name field, a
    built-in base theme, the eight color tokens, font family, text/title/small
    sizes, bar height and corner radius. The page previews the result live.
- **Transparency slider** (0–70 %) that applies in every mode, including while
  following the desktop theme, where the translucent layer uses the inherited
  Plasma colors. Only the background fades: text, icons and bars stay solid, and
  a full-opacity outline keeps the popup's shape readable.
- **Font chooser** — a free-text family field plus a **Choose…** button that
  opens the system font dialog on demand.
- Helper command `usage_monitor_kde.py themes` prints the resolved palette and
  the built-in/installed/custom catalog; the `summary` and `cache` payloads
  carry the theme too, so the panel bar restyles on the next refresh.
- Apply now takes effect immediately: the config pages bump a `stateRevision`
  KConfig key once the helper has written `state.json`, and the applet reloads
  from cache instead of waiting for the next refresh tick.

## Fixed

- **Command-line quoting.** The settings pages passed their payload to the
  helper with hand-rolled escaping, so a single quote in free text (a theme
  name, color or font family) broke out of the shell string. Payloads now go
  through `JSON.stringify` plus the existing `shellQuote`.
- Popup chrome follows the selected theme: toolbar icons, hover/pressed
  backgrounds, busy indicator and scrollbars are painted from the widget palette
  instead of the desktop color scheme, so they no longer disappear on a light
  theme. The usage list also stopped painting the desktop style's opaque frame
  over the widget background.
- Theme editor controls (name, colors, font, sizes) and the transparency slider
  re-sync with the stored value, instead of keeping the previously selected
  theme's values — and writing them into the wrong theme on the next edit.
- Deleting the last custom theme no longer restores the pre-`customThemes`
  palette, and non-finite numbers in `state.json` can no longer produce a
  payload QML cannot parse.
- Scheme mode resolves the selected scheme straight to its file instead of
  rescanning and re-parsing every installed scheme on each refresh tick.

## Changed

- Workspace crate version and KDE plasmoid metadata bumped to `0.8.0`.

## Install

```bash
cargo install usage-monitor-cli
usage-monitor-cli widget install kde
```

Upgrading an already installed plasmoid needs a Plasma restart for the new
config page to appear:

```bash
systemctl --user restart plasma-plasmashell
```
