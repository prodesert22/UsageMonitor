# v0.7.3

Fixes the Kimi provider's usage window mapping against the real API and lets
the KDE panel bar show every usage window a provider exposes.

## Added

- **Kimi total cycle quota.** The `totalQuota` field of the billing API (the
  "uso total" in the Kimi UI) is now reported as a third `Total` rate window,
  next to the 5-hour session and 7-day weekly windows. The KDE popup shows it
  as the Monthly card and the CLI prints it after the weekly window.
- **All windows in the KDE panel bar.** The bar text for the pinned provider
  now joins every window it has (e.g. `28% • 46% • 31%` for session, weekly,
  and total) instead of stopping at the first two. Providers with one or two
  windows keep their previous format.

## Fixed

- **Kimi window mapping.** Against the real `GetUsages` response, the
  scope-level `detail` is the 7-day (weekly) quota and `limits[0]` is the
  5-hour session, identified by its `window` descriptor (`duration` +
  `timeUnit`, with SECOND/MINUTE/HOUR/DAY/WEEK conversion). Previously the
  session was mislabeled as a generic "Rate limit" and the weekly window
  carried no duration, so the two could be displayed swapped.
- Kimi reset timestamps in RFC 3339 form (the format the API actually returns)
  are parsed for every window; epoch-second timestamps remain supported.

## Changed

- Workspace crate version and KDE plasmoid metadata bumped to `0.7.3`.

## Install

```bash
cargo install usage-monitor-cli
usage-monitor-cli widget install kde
```
